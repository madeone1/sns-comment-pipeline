# 액세스 토큰으로 수집 계정·지역 변경

[change-access-token.command](change-access-token.command)를 열어 토큰을 숨김 입력합니다. 별도 웹 호스팅은 필요하지 않습니다. 회사 Google Cloud 계정 `syan@madeone.kr`의 기존 CLI 인증을 사용하며, 인증이 없으면 `gcloud auth login syan@madeone.kr`으로 로그인합니다.

토큰으로 접근 계정을 끝까지 조회하고 계정·게시물·댓글 접근을 확인합니다. 기존 계정 ID는 저장 경로·시트·검수 이력을 이어 사용합니다. 처음 보는 계정만 지역 표시명을 입력하며, 빈칸이면 이번 대상에서 제외합니다. 검증 실패나 불완전한 조회는 기존 연결을 유지합니다.

검증된 연결을 저장하면 수집 작업을 바로 시작하고 시트·노션의 실제 반영을 대조합니다. A·B·C에서 A·D·E로 바뀌면 B·C 탭은 숨겨 보존하고, 노션의 현재 요약에는 A·D·E만 포함합니다. 제외된 지역의 기존 보고는 이력 토글에 보존합니다. 새 지역은 수집되기 전까지 정상 0건으로 표시하지 않습니다.

확인만 할 때는 `./change-access-token.command --check`, 반영 상태는 `./change-access-token.command --status`를 사용합니다. 토큰값은 명령 인자·설정 파일·시트·노션에 기록하지 않습니다. 운영은 Secret Manager의 검증된 고정 버전을 사용하며, 매일 08시에도 토큰 저장소의 변경을 확인합니다. Cloud Console에서 직접 바꾼 새 토큰에 미등록 지역이 있으면 로컬 파일에서 매핑을 확인할 때까지 출력을 보존합니다.

아래의 웹앱·과거 배포 수치와 미연결 기록은 당시 이력입니다. 현재 운영 절차는 위의 로컬 토큰 입력 경로입니다.

사용자는 **세 계정을 묶어 승인한 액세스 토큰 하나**를 발급했습니다. UI 화면 이름만으로 계정별 Instagram 로그인 토큰이라고 단정했던 설정을 정정했습니다. 부산·속초는 `meta_credential: primary`로 기존 official과 같은 토큰을 사용하는 설정입니다. 화면에 계정이 표시된 사실과 그 토큰의 실제 조회 가능 여부를 구분합니다. `100/33` 오류만으로 묶음 발급 자체가 불가능하다고 판정하지 않습니다.

우선 `diagnose-accounts.command`를 열어 같은 토큰을 숨김 입력하면 Facebook Graph의 토큰 주체, 권한, 할당 Instagram 계정·연결 페이지 목록, 대상 계정 객체의 접근을 나누어 확인합니다. 이 진단은 토큰·설정·Notion을 변경하지 않습니다. 결과의 계정 ID 조회 성공은 댓글 권한·실제 수집 성공과 구분합니다. `.local/account-connection.json`에는 대상 계정과 안전한 상태·오류 코드만 남깁니다. 진단이 해당 토큰 유형에 맞는지는 실제 응답으로 확인해야 하며 다른 호스트로 자동 전환하지 않습니다.

`connect-accounts.command`는 토큰을 한 번 입력받고 세 계정을 모두 검증한 뒤에만 공유 토큰을 키체인에 등록합니다. 일반 시스템 사용자 토큰에서 계정 목록을 제공하지 않으면 숫자 Instagram 계정 ID를 입력받아 다시 확인합니다. 하나라도 실패하면 토큰을 교체하거나 계정을 활성화하지 않습니다. 댓글 수집·클라우드 Secret 갱신·예약 변경은 포함하지 않습니다.

```sh
python3 -m sns_comment accounts list
# 현재 묶음 토큰 조회 진단: 토큰·설정 저장 없음
python3 -m sns_comment accounts diagnose --credential primary
# 세 계정 검증 후 공유 토큰 등록. 토큰을 명령 인수에 넣지 않습니다.
python3 -m sns_comment accounts connect --credential primary
# 연결 성공 후 계정을 명시해 수집·확인
python3 -m sns_comment run --account waterbomb_busan_official --until-complete
python3 -m sns_comment summary --account waterbomb_busan_official
python3 -m sns_comment.counts --account waterbomb_sokcho_official --recent
# 같은 묶음 인증의 다음 계정 추가
python3 -m sns_comment accounts add --username another_official --credential primary --account-id 숫자_ID
```

기존 계정의 DB와 경로는 유지합니다. 추가 계정의 DB·실행 로그·시트 내보내기는 `.local/accounts/<아이디>/`에, 클라우드 원본·진행 상태·보고 재시도 자료는 `accounts/<아이디>/` 아래에 분리합니다. 다른 계정 DB를 잘못 지정하면 수집 전에 중단합니다. 기본 계정은 `default_account`, 추가 계정별 설정은 `accounts`에 보관합니다. `meta_credential: primary`는 토큰을 공유한다는 명시적 설정입니다. 별도의 Instagram 로그인 방식도 선택적으로 지원하지만 현재 사용자가 발급한 토큰 유형으로 단정하거나 강제하지 않습니다. 추가 계정은 기존 Google Sheets 대상을 상속하지 않습니다.

Notion은 **기존 계정용 MCP OAuth 연결과 갱신 경로**를 유지합니다. 같은 날짜의 `SNS Comments` 안에 @아이디별 자동 보고를 두며 재실행은 해당 계정·집계 날짜 보고만 갱신합니다. 개별 실행은 `--account`, 정기 세 계정 실행은 `--all-accounts`로 선택합니다. 공유 OAuth 갱신과 보고 쓰기는 기존 전역 잠금으로 직렬화합니다. 11월 6일의 연결·일회성 보고 검증과 11월 9일의 정기 운영 배포를 구분합니다.

묶음 승인 유지와 읽기 진단의 회귀 테스트를 추가했습니다. 세 계정의 보고 공존·선택 계정만 갱신, API 호스트별 허용 경로, 공유 인증과 선택적 Instagram 로그인 방식 구분, 토큰 주체 조회 성공과 자산 조회 실패의 구분, 검증 실패 시 설정 보존, 다른 계정 DB의 수집 차단, 기존 MCP OAuth 유지를 검증합니다. 토큰·원문 API 응답은 진단 파일에 저장하지 않습니다. 새 토큰의 실제 입력·부산 및 속초 실제 API 검증은 별도이며 테스트 통과로 연결 완료를 표시하지 않습니다.

## 전달받은 Notion MCP 토큰 테스트

`test-notion-token.command`를 열면 토큰을 화면에 표시하지 않고 입력받습니다. 브라우저 계정 연결 없이 공식 Notion MCP에 접속해 보고용 도구 권한, 규정집과 일일 업무 데이터 소스의 조회를 검사합니다. 토큰은 메모리에서만 사용하며 결과만 `.local/notion-mcp-token-test.json`에 보관합니다. 이 테스트는 Notion 문서를 수정하지 않으며 조회 성공과 실제 보고 쓰기 성공을 구분합니다.

연결 상태와 대상 문서 접근 상태는 별도로 남깁니다. `mcp_connected=true`인데 `status=target_access_failed`이면 초기 MCP 연결 뒤 설정된 문서 조회·검증에서 실패한 것입니다. `checks`에서 규정집·일일 업무 데이터 소스 중 실패한 대상과 서버가 제공한 오류 코드·상태를 확인합니다. 토큰이 잘못됐다고 단정하지 않으며, 서버의 원문 오류 메시지는 저장하지 않습니다. `get-self`가 제공되면 연결된 워크스페이스도 조회합니다. 조회가 성공해도 쓰기 도구 권한이 없으면 `report_ready=false`입니다.

실행기는 `--diagnose`를 함께 사용합니다. 같은 토큰으로 사용자/봇 식별값(이메일 제외), 실제 fetch 입력 스키마, 규정집 전체 URL 2종, 일일 업무 상위 DB의 ID와 URL, 문서명 검색을 비교해 `diagnostics`에 남깁니다. 문서별 권한, 대상 식별값, 호출 형식 차이를 구분하기 위한 읽기 진단이며 404만으로 권한 부족을 확정하지 않습니다. 권한·설정 ID·Notion 본문을 자동 변경하지 않습니다.

```sh
python3 -m sns_comment.notion_token
# 같은 토큰으로 요청 형식·검색·사용자/봇을 함께 대조
python3 -m sns_comment.notion_token --diagnose
# 지정 날짜의 일일 업무까지 읽기 검증
python3 -m sns_comment.notion_token --day 2026-11-06
```

별도 진단 실행기에서는 `SNS_NOTION_MCP_TOKEN`도 사용할 수 있습니다. 토큰을 명령 인수나 채팅에 넣지 않습니다. **2026-11-06 운영 방식 정정:** 이 토큰으로 Cloud Run 인증을 자동 전환하던 경로는 제외했습니다. Cloud Run은 이 환경변수가 있어도 진단용으로 무시하며 기존 MCP OAuth 연결만 사용합니다. 진단 도구는 별도로 보존하고 자동 실행에 연결하지 않습니다.

2026-11-06 전체 로컬 테스트 **163건 통과**(기존 145건 + MCP 토큰 회귀 18건). 긴 토큰의 전체 전달·비노출, 거부된 토큰의 OAuth 갱신 방지, 숨김 입력 실패 시 중단, 조회 테스트의 쓰기 금지, 기존 OAuth 경로 유지, 연결 성공 뒤 문서 접근 실패의 구분, 안전한 오류 코드 표시, 전체 URL·검색·상위 DB 대조와 사용자/봇 구분을 합성 응답으로 검증했습니다. 전달받은 실제 토큰의 결과는 입력 후 별도로 확인해야 합니다.

## 실행

Python 3.10 이상과 표준 라이브러리만 사용합니다. 공개 설정은 `config.json`에 보관합니다. macOS에서는 `run.command`를 더블클릭하거나 아래 명령을 사용합니다.

```sh
cd /Users/wonsh/project/sns-comment
# 기본: 최근 7일에 작성된 게시물만 수집
python3 -m sns_comment run --until-complete
# 최근 댓글 활동이 확인된 이전 게시물만 별도 실행
python3 -m sns_comment run --tracked --until-complete
# 추적 목록 조회: Meta 토큰·네트워크 요청 없음
python3 -m sns_comment tracking list
# 알려진 계정 소유 게시물에 최근 댓글이 달린 것을 사람이 확인한 경우
python3 -m sns_comment tracking add --media-id 숫자_ID --activity-at '2026-11-05T10:00:00+09:00'
# 원본 DB의 최근 게시물 댓글 수만 즉시 확인: 토큰·네트워크 요청 없음
python3 -m sns_comment.counts --recent
# 기본 범위만 시트 반영 자료로 내보내기
python3 -m sns_comment sheets export
```

`count.command`도 최근 게시물의 저장된 기간 댓글 수를 즉시 계산합니다. 누적 댓글 카운터와 다릅니다. `run --tracked` 결과와 기본 보고는 별도 작업 ID와 통계로 구분합니다. 예전 전체 순회 작업 ID는 최근 게시물 실행에서 재개하지 않습니다.

기존 official 계정은 회사 포트폴리오의 일반 시스템 사용자 토큰과 `graph.facebook.com`을 사용합니다. 부산·속초는 사용자의 묶음 승인 방식으로 설정했으며 실제 새 토큰의 계정 접근·적합한 조회 경로는 진단 응답으로 확인해야 합니다. 매 실행 때 선택 계정의 ID와 @아이디 일치를 검증합니다. API 오류를 이유로 같은 토큰을 다른 호스트에 재전송하지 않습니다. 토큰은 계정 설정에 맞는 환경변수·macOS 키체인 또는 터미널 숨김 입력으로 공급합니다. 연결 실행기로 등록하면 macOS 키체인에 보관하며, 설정 파일·DB·시트·노션·로그·URL에 저장하지 않습니다. ## 병렬 조회

기본 `collection.workers`는 3입니다. `python3 -m sns_comment run --workers 1`로 순차 대조하거나 `--workers 5`까지 조절할 수 있습니다. 최근 게시물 탐색은 기본 1페이지·최대 50개 메타데이터를 한 번에 받으므로 1,340개 개별 요청이 아닙니다. 목록의 다음 커서는 앞선 응답에 의존하므로 페이지 순서를 유지합니다.

선택된 게시물의 댓글 목록과 서로 다른 부모 댓글의 답글 조회는 최대 3개의 GET 요청을 겹쳐 실행합니다. 같은 댓글·답글 목록의 다음 페이지는 이전 페이지 저장 뒤에 요청하고, SQLite 저장과 체크포인트 갱신은 호출한 한 스레드에서 처리합니다. 확장 응답에 포함된 답글은 먼저 저장하고 불필요한 개별 조회를 줄입니다. 이미 진행 중인 답글과 중복되는 확장 응답은 해당 작업의 완료 상태를 앞당기지 않습니다.

모든 작업이 실행당 요청 예산을 공유합니다. 예산·인증 오류·실제 호출 제한에 도달하면 새 요청을 멈추고 이미 진행 중인 응답을 정리합니다. 실패한 게시물의 완료 시각은 전진시키지 않습니다. 결과 JSON의 `network_workers`, `network_metrics.peak_concurrent_requests`, `api_requests`, `elapsed_seconds`에서 설정과 실측을 구분합니다. 실제 Meta 성능은 실행 후 확인해야 합니다. HTTP 연결 재사용은 별도 최적화 대상으로 남아 있습니다.

## 게시물 발견과 이전 게시물 추적

기본 실행은 게시물 목록 메타데이터를 **기본 1페이지·최대 50개**만 갱신하고, 기존 로컬 캐시에서 작성 기간에 맞는 게시물을 선택합니다. 과거 목록의 나머지 커서를 자동으로 끝까지 따라가지 않습니다. `discovery_exhaustive`는 실제 목록 끝까지 확인했는지를 따로 표시합니다. 제한된 발견 범위를 계정 전체의 신규 게시물 부재로 해석하지 않습니다. 새 게시물이 발견 페이지를 초과하는 운영량이면 `collection.discovery_pages`를 조정하거나 게시물 발견 경로를 보완해야 합니다.

이전 게시물 추적 목록은 저장된 최근 댓글·사람의 확인·검증된 댓글 알림을 근거로 추가하고, 활동 시각이 현재 재조회 기간보다 오래되면 자동 대상에서 빠집니다. 아직 알지 못하는 오래된 게시물의 새 댓글은 전체 순회로 찾지 않습니다. **새 활동의 자동 발견에는 Webhook 수신 연결이 필요하며 현재 미연결입니다.**

`sns_comment/tracking.py`에는 앱 시크릿의 HMAC 서명을 검증하고 해당 계정의 댓글 알림에 있는 게시물만 후보로 등록하는 함수가 있습니다. 본문을 저장하거나 Instagram을 변경하지 않습니다. 알림 도착 시각은 활동 신호이고 댓글 작성 시각이 아닙니다. 집계 전 실제 작성 시각을 다시 확인합니다. 미확인 게시물은 개별 메타데이터 조회로 소유 계정을 검증해야 합니다. 함수 구현·합성 검증을 실제 구독 등록·수신 검증 완료로 표시하지 않습니다.

로컬 테스트 **145건 통과**. 최근 게시물 선택·날짜 경계·활동 추적 분리·토큰 입력·분산 잠금·OAuth 갱신·AI 결과 검증·월간 범위 분리·의도별 건수와 작성자 수·분류 기준 변경 시 캐시 재분류·Notion의 날짜별 제한 쓰기와 재실행 중복 방지를 포함합니다. 수집·AI 분석·Notion 기록은 실제 클라우드에서도 성공했습니다. 실제 Webhook 수신, Sheets/Drive 무인 연동과 개인 알림 전송은 별도 검증 전입니다.

Finder 실행기는 셸을 Python 프로세스로 바로 교체합니다. 시작·종료 상태는 `.local/last-launch.json`에 기록하고, 수집 완료·미완료 표시와 마지막 Enter 입력은 Python에서 처리합니다. 실행 중 셸 스크립트를 수정해 종료 구문 오류가 났던 이력은 아래에 보존합니다.

## 이전 실제 인증·수집 검증 기록

**2026-11-04 게시물 1개 실제 API 검증 완료:** `instagram_basic`·`instagram_manage_comments` 승인과 대상 계정 일치를 확인한 뒤, 지정 릴스의 게시물 ID `18137736370572410`을 해당 계정의 게시물 목록에서 찾았습니다. 댓글 68건·답글 3건, 총 71건을 저장했습니다. 같은 범위를 두 번 수집해 각각 `complete`, API 요청 70회였으며 재실행 뒤에도 고유 댓글 ID와 관측 이력은 각각 71건을 유지했습니다. 새 ID·유실 ID·중복 저장은 없었습니다. 답글 부모 누락과 DB 외래키 오류는 0건, SQLite 무결성 확인은 정상입니다. 이 결과는 API가 반환한 범위의 검증이며 Instagram 화면 전체와의 대조는 수행하지 않았습니다.

총 71건 중 67건에는 본문이 있고, 4건은 API가 `text` 필드를 제공하지 않았습니다. 본문 미제공 항목도 원본 응답과 ID·시각·작성자·부모 관계를 보존하며, DB의 `text`는 `NULL`로 저장합니다. 빈 문자열과 구분하고 누락 원인을 임의로 추정하지 않습니다. `summary`의 `text_available`·`text_unavailable`로 각각 집계합니다. 기존의 본문 필수 DB도 트랜잭션 안에서 원본·관측 이력·키를 유지하며 이관합니다. 관련 로컬 테스트는 26건 통과했습니다.

실제 댓글 DB는 `.local/comments.sqlite3`, 결과 요약은 `.local/pilot-result.json`, 승인 후 상세 실행 기록은 `.local/approved-token-test-report.json`입니다. 토큰은 테스트 프로세스 메모리에서만 사용했고 파일·DB·로그·URL에 저장하지 않았습니다.

[일반 시스템 사용자 토큰 공식 절차](https://developers.facebook.com/documentation/facebook-login/guides/access-tokens/#systemusertokens)

## 실패와 재실행

- 원본은 분석 전에 저장합니다. 같은 계정·댓글 ID는 한 행으로 병합하고, 최초 관측 원문과 이후 다른 관측값은 `observations`에 보존합니다. 같은 문구의 다른 댓글 ID는 각각 보존합니다.
- 페이지 저장과 체크포인트 변경은 같은 트랜잭션입니다. 일부 실패는 `partial` 또는 `failed`로 기록하며 마지막 전체 완료 시각을 전진시키지 않습니다. API 인증 오류나 잘못된 목록 응답을 정상 0건으로 처리하지 않습니다.
- 계정 수집은 저장된 게시물 목록·댓글·답글 커서에서 재개하고, 완료된 게시물은 건너뜁니다. 커서 거부 오류는 해당 경로의 첫 페이지부터 실행당 한 번만 재확인하며 ID로 중복을 방지합니다. 커서가 반복되면 미완료로 남깁니다. 게시물 1개 진단은 이전처럼 처음부터 재조회합니다. 답글 확장이 없으면 개별 답글 조회로 확인하고 오래된 부모 댓글도 조회합니다.
- 동일 DB의 수집 실행은 파일 잠금으로 중복 실행을 막습니다. 강제 종료로 남은 `running` 기록은 다음 수집 때 `interrupted`로 바꿉니다. 저장된 DB는 유지합니다.
- 실행당 최대 500회 요청, 계정 게시물 목록 최대 20페이지를 기본 상한으로 둡니다. 이는 수집 대상을 잘라내는 기준이 아닌 실행 예산입니다. 초과 시 `partial`·재개 명령·미완료 게시물 수를 반환합니다. 목록 끝을 확인하지 못했으면 전체 게시물 수는 미확정입니다. `--max-requests`, `--max-media-pages`로 조절하며 API의 실제 호출 제한과 구분합니다. 실제 호출 제한·인증 오류·서버 오류에서는 다른 게시물로 불필요한 요청을 이어가지 않습니다.
- 수동 파일럿은 오류 후 자동 재시도하지 않습니다. 저장된 원본·상태를 확인하고 재실행합니다. 매일 운영용 5분 간격 최대 3회 재시도와 알림은 후속 구현 항목입니다.
- HTTP 리다이렉트는 따라가지 않습니다. 페이지 응답의 `next` URL은 호출·저장하지 않고 `after` 값만 고정된 GET 경로에 적용합니다. 원본에 확장 페이지 URL이 섞여 저장되지 않도록 답글 원문을 분리합니다.
