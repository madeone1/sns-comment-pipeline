# YouTube 데이터 보유·철회·삭제 운영안

2026-11-16 점검. **검토용 운영안이며 아직 운영에 적용되지 않았다.**
이 문서는 YouTube 원본 댓글의 삭제를 지시하지 않는다. 앱이 저장한 사본만 대상으로 한다.

이번 점검에서는 운영 댓글·시트·토큰·예약·보존 설정을 변경하지 않았다.
DB 본문의 로컬 다운로드는 자동 승인 검토에서 거절되어 수행하지 않았다.
이후에는 설정, 객체 메타데이터, 집계 및 시트 ID 열만으로 범위를 좁혔다.

## 저장·갱신 운영안

- 기준은 댓글 작성일이 아니라 **API로 마지막 확인한 시각**이다. 오래전에 작성된 댓글도 최근에 정상 갱신했다면 작성일 때문에 제거할 이유는 없다.
- 현재 댓글 목록은 일일 전체 순회로 갱신하되, 이전 원본 응답·과거 관측 이력은 별도로 만료시킨다.
- 제안: 원본 응답 및 갱신되지 않은 원문은 21일 시점부터 정리 대상으로 삼고, 7일 복구 보관과 처리 지연을 포함해 30일을 넘기지 않도록 확인한다. 단, 자동 만료는 정확한 완료 시각을 보장하지 않으므로 매일 만료 미완료를 감시한다.
- DB는 comments만 정리하면 충분하지 않다. observations/runs에 원문이 남는지 확인하고, pipeline_seen/cursors/page_tokens와 Sheet 행 캐시를 함께 처리한다. VACUUM 이후 승인된 새 체크포인트를 저장한다.
- 시트 동기화는 DB에서 사라진 ID의 예전 A:R 셀을 정리해야 한다. 현재 sync는 고아 행을 제거하지 않으므로 DB 정리만으로 사본 삭제가 완료되지 않는다.
- 별도 `처리 이력` 탭과 S:Z의 사람 입력 메모는 파이프라인 소유 범위와 구분해 점검한다. 임의의 전체 시트 초기화는 하지 않는다.
- 운영 계정이 복구한 과거 DB가 삭제된 데이터를 되살리지 않도록 삭제 요청의 최소한의 차단 기록을 두고, 복원 전에 이를 적용한다. 차단 기록에는 원문·작성자 프로필을 보관하지 않는다.

## 소유자 연결 해제 요청

1. 요청자의 채널 권한, 대상 채널, 요청 시각, 요청 범위와 처리 기한을 확인한다. 원문을 요청 접수 기록에 복사하지 않는다. 담당 연락처 제안은 syan@madeone.kr이며 실제 운영 담당자 확인 후 공개한다.
2. 확인된 요청에 한해 전용 youtube-comments-daily 예약과 재수집을 중단한다. 네트워크 장애를 동의 철회로 단정하지 않는다. 채널 소유·OAuth 오류를 재확인한다.
3. 앱 내부에서 연결 해제를 처리하는 경우 해당 YouTube OAuth 토큰을 Google 공식 revoke endpoint로 철회한다. 다른 서비스의 OAuth·프로젝트 인증은 건드리지 않는다. 전용 Secret 버전·로컬 데모 인증정보까지 목록화한다.
4. 원문 처리는 승인된 클라우드 런타임 내부에서 수행한다. 운영 DB를 점검자의 컴퓨터로 내려받지 않는다. 대상 댓글과 원문이 담긴 관측·실행 기록, 원본 응답, Sheet 및 로컬 사본을 삭제 계획에 포함한다.
5. 라이브 객체 삭제와 복구 보관본의 완전 만료를 구분한다. 복구 보관본은 API로 내용을 읽을 수 없지만 승인된 관리자가 복원할 수 있다. 따라서 이를 삭제 완료로 단정하지 않는다.
6. 현재 GCS soft delete의 활성 보존 기간은 최소 7일이며, 0으로 비활성화하는 선택지만 그보다 짧다. 변경은 향후 삭제에만 적용되며 기존 복구 보관본의 만료를 당길 수 없다. 복구 보호를 비활성화하려면 소유자의 별도 승인이 필요하다.
7. 활성 데이터, 복구 보관본, 시트, 로컬 사본과 토큰까지 검증한 뒤 처리 결과를 회신한다. 미완료 사본과 물리적 만료 시각이 있으면 함께 알린다. 원문 없는 최소 삭제 영수증만 보관한다.

## 개별 작성자·댓글의 사본 삭제 요청

- 요청자가 지정한 댓글 ID 또는 작성자 채널 ID를 본인 확인과 함께 처리한다. 댓글 텍스트만으로 범위를 추정하지 않는다.
- 혼합된 원본 응답 파일에 다른 댓글도 들어 있으면, 클라우드 내부에서 해당 데이터를 안전하게 제거하거나 더 넓은 원본 캐시 정리 범위를 먼저 승인받는다.
- 원댓글 사본을 지워도 연결된 답글의 작성자가 다를 수 있다. 삭제 범위를 사용자별로 확인한다.
- 원본 YouTube 댓글과 앱 사본의 삭제는 별개라고 알린다. API의 comments.delete나 setModerationStatus를 사본 삭제 용도로 호출하지 않는다.

## 제출 전 완료 기준

1. 시트 중복과 정상 정기 동기화 복구 확인.
2. 승인된 담당자·공유 대상 확정.
3. 클라우드 내부 보유·삭제 실행기 및 시트 고아 행 정리를 구현·검증·배포.
4. 기존 복구 보관본과 향후 복구 정책이 요청 처리 기한을 만족하는지 확인.
5. 실제 동작과 일치하는 앱 소개·개인정보처리방침·약관을 게시하고 OAuth 링크를 확인.
6. 검토용 데모를 최종 상태에 맞춰 확정, 사용자 검토 후 YouTube 일부 공개 업로드.
7. 실제 영상 URL을 등록한 뒤 제출 화면의 오류가 사라졌는지 확인. 이 점검만으로 법적 동의나 정책 준수를 대리 확약하지 않는다.

## 읽기 전용 도구

```sh
.venv/bin/python -m youtube_validation.privacy_audit \
  --state .local/youtube-validation \
  --objects .local/youtube-oauth-review-2026-11-16/objects.json \
  --soft-deleted .local/youtube-oauth-review-2026-11-16/soft-deleted-objects.json \
  --output .local/youtube-oauth-review-2026-11-16/privacy-audit.json
```

도구는 원본을 변경하지 않으며 삭제 실행 옵션이 없다. 출력은 오래된 로컬 사본과 현재 클라우드 메타데이터를 구분한다.

공식 기준: [YouTube 개발자 정책](https://developers.google.com/youtube/terms/developer-policies), [GCS soft delete](https://docs.cloud.google.com/storage/docs/soft-delete), [Google 민감한 범위 심사 영상](https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification).
